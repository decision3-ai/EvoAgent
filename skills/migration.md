# Migration Skill

## When to use
- Any DB schema change (new column, new table, index, constraint)
- Never use create_all() in production

## Steps
1. Make the SQLAlchemy model change first
2. Generate migration: docker exec agentevo_api_1 alembic revision --autogenerate -m "description"
3. Review the generated file in migrations/versions/ before applying
4. Apply: docker exec agentevo_api_1 alembic upgrade head
5. Tell Victor exactly what changed in the DB

## Rules
- Never edit an already-applied migration file
- Migration description must be clear: "add_evo_points_to_workspaces" not "update"
- Always check the autogenerated file — Alembic sometimes misses things
- pgvector columns: type is Vector(768), import from pgvector.sqlalchemy
